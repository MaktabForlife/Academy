# Academy announcement PDFs V106.67

Global Admin can upload one PDF up to 10 MB, independently of the existing poster upload (up to 5 MB). Selecting a PDF inserts a named Read PDF link into the message. The label can be edited, and Insert PDF link in message restores it without duplication. The PDF is uploaded on Save announcement. Ordinary edits preserve existing attachments; replacement retains the announcement PDF address, and removing a PDF removes its generated message link. An attachment link is also shown for PDF-only messages and whenever its message has no attachment link.

Messages render pasted HTTPS addresses and [link text](https://example.com/file.pdf) as clickable links. Text and link labels are escaped, unsafe protocols and credential-bearing URLs are rejected, and new tabs use noopener/noreferrer. Message line breaks are preserved within the existing compact, scrollable announcement card.

PDF bytes use the existing LESSON_MEDIA_BUCKET with per-announcement, per-operation content hashes. MIME, extension, signature and size are checked before storage, and the entire multipart request is bounded. Metadata is one indexed academy_settings entry per PDF, joined into the announcement query; it requires no schema migration or additional per-announcement public query. Only active, undeleted announcements expose their attachments to visitors. Global Admin may read an inactive attachment through the authenticated API; scoped admins, Teachers and Students have no draft access. Responses stream application/pdf with nosniff and no-store, and support GET and HEAD. Bucket keys remain private.

Save/delete reuse the existing scoped conflict guards, transaction-time account/session/Global Admin checks, audit records and exact-payload retry receipts. Metadata and announcement changes commit together. Old objects are deleted only after a successful commit and only when no current announcement references them. Failed uploads/commits attempt safe cleanup while preserving the prior attachment. Older clients can omit the new PDF fields without dropping a saved PDF or changing pre-upgrade retry hashes.
