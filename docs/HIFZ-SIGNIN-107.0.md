# Academy V107.0 / Hifz V5.0 — Shared PIN credentials and Academy-to-Hifz sign-in

Academy links open Hifz development at `https://hifz.maktab4life.org/<loginID>?academy=1`. Hifz creates a random PKCE verifier and state in that tab, redirects to Academy's small `/academy/hifz/` bridge, and exchanges the current authenticated Academy session for a one-use Hifz code. Academy checks the current session, credential epoch and effective Hifz membership. The receiver applies the signed current profile before minting the code. The browser receives no PIN hash, pepper or Academy token from the other application.

Hifz accepts the code only with the original tab's verifier, its allowed frontend origin, a current active local profile and the same local credential epoch. It atomically deletes the stored code digest when consumed. Codes expire after 60 seconds. The browser removes the code fragment immediately; redirects and authentication responses are not cached. No caller-supplied return address is accepted.

Both systems use the versioned v3 salted PBKDF2-HMAC-SHA256 credential contract (100,000 native Workers iterations, 16-byte random salt, 32-byte derived key) and the same separately configured `SHARED_PIN_SECRET` in development. The native Workers iteration ceiling is 100,000; this release adopts Academy's stronger hashing method rather than Hifz's previous single SHA256 digest. Existing Academy v2/legacy credentials verify with the original secret and upgrade on the next successful Academy PIN sign-in. The original PIN remains unchanged. Old Hifz credentials also upgrade on successful local verification until the Academy credential is delivered; the Academy copy then becomes authoritative.

New/reset PINs for linked users are chosen and confirmed only in Academy. The durable outbox delivers the exact shared credential privately to Hifz; hashes never enter frontend profile APIs or logs. A changed hash or Academy reset clears Hifz lockout and increments its session epoch. Direct Hifz access verifies the shared PIN locally. Normal journal requests never call Academy.

Schema additions are Academy migration `0029_hifz_shared_pin.sql` (enqueue PIN setup/upgrades and replay current profile metadata once), Hifz migration `0033_academy_handoff.sql` (source epoch and indexed temporary code digests). No journal owner or journal entry is rekeyed. Production remains unchanged. The Hifz repository is copied with main/dev history to `MaktabForlife/Hifz`; the separate Hifz Cloudflare account, Worker and D1 remain in use.

Rollout: rehearse migrations and negative authentication cases; configure the matching development-only secret; apply Hifz and Academy additive migrations; deploy the Hifz receiver before Academy can send shared credentials; publish matching frontends and test the full browser handoff plus direct PIN login, replay rejection and reset revocation.
