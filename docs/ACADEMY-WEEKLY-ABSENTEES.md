# Dashboard attendance and weekly absentee list

V107.103 follows V107.102 on feature/academy-weekly-absentees. The user approved Monday 08:00 Riyadh in-app delivery and deployment after local testing.

Attendance panels, quick actions, workspace-menu entries and background register loading are removed from every dashboard audience. Other attendance screens, access checks, submissions and corrections are unchanged. The calendar now occupies the available width. Dashboard refresh no longer enumerates activity/date pairs or calls attendance/get.

The existing Messages inbox receives one system notice per active Admin each Monday at 08:00 Riyadh (05:00 UTC). The period is the previous Monday–Sunday, using the saved register attendance dates in each area's configured timezone. Global Admins can open all saved areas; other Admins see only current authorised areas. Personal Learn/Teach and Admin-Learn/Admin-Teach cannot open these reports. Ordinary message composition cannot create system reports.

Generation copies only sparse ABSENT entries in the latest submitted register versions and their frozen roster names/lesson context, for required contexts. Unsubmitted registers are unknown and excluded. A corrected register whose latest version records attendance is excluded. A later correction does not rewrite a previously issued weekly snapshot; the ordinary attendance tools retain the current record. Notices with no absentees explicitly say so. Activity labels are resolved from accepted setup when the report is opened.

Generation is one guarded atomic Core transaction. It reads no live enrolment, eligibility or reconstructed roster projections. Unique period and recipient keys prevent duplicates. Failures roll back the entire run. A dedicated weekly cron retries at 15-minute intervals through 09:45 Riyadh, then stops. Successful retries read only the indexed report key. Existing minute and cache-recovery schedules do not run this job. Inbox counts/listing read only indexed report metadata and receipts, never absence rows. Opening the report checks live Admin authority and filters snapshot rows by current scope; revoked roles cannot recover historical private content from retained notices.

Required additive migration: backend/migrations/academy-core/0005_weekly_absentees.sql, applied only to existing Core. It creates three private operational tables and indexes, including a date index on attendance_days. Split fences and epoch triggers cover all new tables. No Admin schema changes, backfill, live attendance edits, timetable publication or historical report generation are required. The unsplit migration 0040_weekly_absentees.sql is only for disposable fixtures. Deploy matching coordinator layout metadata before API and website; retain all IDs, accepted heads, secrets and existing variables. New API setting ACADEMY_WEEKLY_ABSENTEES=1 enables system notices and weekly generation.

Keep live checks small to limit database usage. Validate with disposable local databases and browser accounts. Live verification is limited to schema metadata, deployment/schedule management metadata, version/static assets and one readiness request. Do not trigger report generation or open real attendance dashboards as a smoke test.
