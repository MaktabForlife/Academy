# First publication of new Courses — local candidate

This feature starts Studio access setup only when a newly created Course is first published through Academy's existing validated, accepted Course editor. Draft saves, ordinary reading, opening media and later publications do not start another handover. New copies and repeats have their own Course identity. Copying learners retains the editable roster; it does not copy purchases. A paid new Course requires its own purchase.

Creation and first publication are marked only while `ACADEMY_WEB_PLATFORM=1` and `ACADEMY_COURSE_STUDIO_PUBLICATION=1`. The new flag is absent from the release configurations. Core migration `0016_course_studio_publication.sql` seeds no Course, mapping or transfer. Existing Courses and drafts, including the five unmapped records, are excluded. Backfilling one needs a separately reviewed mapping and handover. While the new flag is enabled, legacy subject-creation requests must use Course management instead, so they cannot create an unmarked new Course. Existing legacy Courses and calendar operations remain available.

The normal current-session, credential-epoch, scoped role, revision and validation guards remain in force. The publication transaction records the accepted title/time zone, native publication ID, stable registration ID, Course mapping and durable job, and freezes Academy access edits together. A failed transaction rolls everything back. Pre-publication rights are imported unchanged; first publication creates no enrolment or purchase. Free enrolment remains separate from a purchase and material access follows the published Free policy.

One bounded background step resumes one job through registration, existing indexed import/outbox delivery, exact participant pages and the shared guarded handover. The original publisher's expired or revoked session is not reused. Academy's current master, staff, class, timetable and Zoom facts remain authoritative. A short compare-and-set retry lease rotates pending jobs fairly. There is no account sweep, browser polling or per-file Academy call. Import pages contain at most 25 source records and handover pages at most 25 people.

A lost/unknown response leaves Academy FROZEN. Retrying uses the same registration and operation receipts. A changed checkpoint is cancelled permanently before a new checkpoint starts, without unlocking Academy. Academy becomes STUDIO only after Studio confirms COMMITTED. Manual handover commands cannot abort an unfinished automatic job. The Course screen shows pending/completed setup passively; an actual current Course Admin or Global Admin can request one Resume step, guarded against unsaved edits. Cron and the existing accepted-write recovery continue delivery.

This candidate adds no teaching website, material publication, media attachment, storage copy, live permission grant, old-screen retirement or DNS change. It does not fix the separate legacy Academy media-authority path. The previous Tafseer/Kahf ownership and all existing content stay intact.
