# Academy Admin → Studio access integration (local only)

The paired target implementation and guarded handover plan are documented in AcademyStudio `docs/STUDIO-ACCESS-MANAGEMENT.md`. Use branch `feature/academy-studio-access-admin` together with `feature/studio-access-management`. This is local preparation; V108.4 source and V108.5 target remain live. The dashboard changes `804c4e1b` / `8746806` are local, not a deployed or authorised V108.6. Do not deploy, activate hosted schemas/ownership or publish under this handoff.

The new source endpoint `/api/admin/platform/studio-access` is an exact-origin POST inside actual Academy Admin. It verifies the current native bearer session/workspace and current Core identity/admission/epoch, resolves the offering mapping, and signs a server-only actor proof capped at 55 seconds and the actual Academy session expiry plus the bounded current deliveries. The target rechecks the exact current staff scope and guards the final mutation. Browser actor/role/offering hints cannot confer authority. No extra workspace/menu item or separate login is added.

Native Programme/Course Participants mount the shared learning-access component. Once the signed read confirms Studio ownership, the client skips the legacy full participant reader and uses target keyset pages of 25 and exact-person rights. Non-migrated programmes retain the legacy tools. Explicit Save batches participation/month/grant changes; removals require reasons. Successful empty reads have revision-based reuse and are cleared on account changes. Pending enrolments resume their server receipt; identity creation/linking happens first in Academy, with no implicit purchase.

`0015_studio_access_admin.sql` adds only the ownership/fencing structures and indexes. It seeds no transfers. During FROZEN, old scoped access/staff edits are rejected. After STUDIO, Student/access changes remain fenced while Academy staff-role edits reopen. Staff remains Academy-owned in this phase, as do master accounts, admissions, sessions, class memberships and timetable/Zoom/lifecycle. Target staff edits are denied. Current suspended master snapshots can transfer retained purchases without allowing entry. Reviewed migration-scope availability is separate from the archived/cancelled live lifecycle; retired billing-policy edits are fenced. Current staff/class facts keep flowing; source projections no longer query frozen purchase/month/grant history after handover. A staff removal/downgrade closes both the signed proxy and existing native Studio admin/editor sessions on receipt; sensitive freshness remains 60s. Normal account/live proofs remain 43200s.

Global Admin handover commands are source-orchestrated: start → bounded reconcile/delivery → exact participant checkpoint pages → commit. Browser-supplied participant counts/versions/final flags are never trusted. A raw target authority flip is blocked. Unknown target commit outcome leaves Academy FROZEN for an exact retry. Abort first confirms/aborts the target checkpoint, then unfreezes; COMMITTED cannot automatically roll back. Master/account/session and timetable streams continue independently. The same Participants screen provides a narrow source-owned Tafseer class/date editor after confirmed Studio enrolment. It uses current actor/ownership/class guards, exact row concurrency and receipt retries; it never creates a source Student role or material rights. Current classes/windows are bounded, historical records are retained and delivery stays change-driven. Refer to the target plan before any separately approved activation.

Core/session checks, source outbox/recovery and target mutations are exercised together in target `tests/studio-access.test.mjs` using disposable native Workers/D1/R2 fixtures. Source Course-management and monthly-register UI/management checks remain separate. Preserve all original 49 enabled media references and existing native login/dashboard/navigation during any later local composition.

The bridge caps browser commands at 128 KiB and signed envelopes below 250,000 bytes. It drains and acknowledges accepted source deliveries before retrying a large command, and acknowledges them even when the command needs a validation correction. Website-only paid months remain separate from recording cohorts. Prepared identity intents can resume under a fresh current session after credential epoch changes; expired sessions cannot. Client account restoration and delayed prior-account responses clear private panes without polling.
