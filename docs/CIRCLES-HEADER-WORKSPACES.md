# Native page header workspace selectors

The single Dashboard button is replaced by one Learn / Teach / Admin selector row on Academy programme pages and standalone tools. The current verified audience is highlighted. Existing native availability controls each choice; Global Admin has all three, a personal teacher has Learn/Teach, and a learner has Learn. An unverified Admin address exposes no private selector row. The account's separate role/read-only context remains available.

Connected pages use the existing checked, account-token-bound Circles return context. Its narrow `modeHref(mode)` accepts only Learn/Teach/Admin and constructs a root workspace hint on that context's already checked website origin; it accepts no URL/origin from the button or query. Circles still verifies the account and requested view. The header waits for the existing asynchronous return-module/owner check before choosing a continuation, then rechecks owner, availability and unsaved-work guards. A changed or expired owner cannot produce a connected URL. Pages without a connected context retain checked native workspace navigation.

Both native `data-academy-tab` and standalone `data-shell-role` controls share the same labels, highlight and equal-height styling. Hidden choices stay hidden. All three native entrance choices go through the shared navigation/dirty guards, including the new Access editors. Existing page actions, account switching, history and teaching/assessment/media capabilities are unchanged. This does not add a Studio Teach delivery mode; Studio's existing Learn/Admin boundary remains separate.

The lightweight preview reached the programme via the checked connector and native Coming up next link; it is not a new programme-card regression claim. Broader circle/programme UI remains with Circles.
