# Native content media

This local feature follows the reviewed academic editor/read-budget branch. It supplies functional Source forms and contracts for later paired Academy/Studio composition; it performs no deployment.

## Native authoring

The normal native UI requests `feed` with `contentFlow:true` and exposes **Add media** to current scoped Admins. Programme media follows native Programme → Class → Subject/Module or Surah → registered Teacher. Course media attaches directly to the Course and registered Teacher. Names appear in the UI; IDs remain internal form values. A recording date anchors class/month audiences. No timetable, delivery/run, session or publication is created or required.

`POST /api/academy/lesson-media/binding-options` accepts `{activityKey,classId?}`. Its `ACADEMY_MEDIA_CONTEXT_V2` response contains named `classes`, `subjects`, `teachers`, `teacherRequired:true`, `timetableRequired:false` and an actor/epoch/native-options/ownership-bound `optionsRevision`. Programme subjects include active native subjects/modules and `SURAH:<native ID>`; Course uses one internal `COURSE:<native activity ID>` choice and no classes. There is no authoritative class-to-curriculum permission mapping in the current schema. `class_module_progress` describes progress, so choices stay within the selected native Programme without inferring year/class associations from names.

`POST /binding-create` accepts `{activityKey,classId?,subjectKey?,recordingDate,teacherIds,optionsRevision,operationId,title?}`. Programme class/subject and one to ten distinct checked native Teacher IDs are required. Course requires no class/run/session. The deterministic ID is `LM-CONTENT-` plus the SHA-256 of activity/operation. Existing actor-bound receipts handle exact retry; conflicting details under the same operation ID fail. Choices are re-read before the guarded write. Actual current Admin scope, session, epoch and active activity remain required. Teach/Learn/preview cannot create or correct native content.

**Save private draft** and **Publish media** are separate actions. Publication uses the existing per-change acceptance wrapper in `m4l-academy-workspace.js`. Saving a previously published row leaves the accepted learner version in place until explicit publication. V2 recorded-context corrections also become drafts. Existing legacy one-day corrections remain compatible. Hide retains immediate visibility suppression. Legacy create/calendar/timetable APIs remain for compatible callers; the new UI never calls them.

The form keeps unsaved values on cancellation/stale responses, refreshes changed native choices while preserving entries, reuses the exact payload after uncertain acknowledgements, and clears private state/ignores late replies when account/session/workspace changes. Teacher labels have full touch targets. Circles owns the final shared presentation and complete Admin-entry integration.

## Storage and authority assessment

No new table, column, schema version or migration is needed. Existing dated lesson storage and immutable note snapshots are sufficient. The sole first `source_lessons_json` element stores `schema:'ACADEMY_MEDIA_CONTEXT_V2'`, `binding:'PROGRAMME_SUBJECT'|'COURSE'`, native activity/class IDs, recording date, name snapshots and a `RECORDED_LESSON_CONTEXT_V1` recorded subject/Teacher context. Physical `media_scope:'SESSION'` is the existing dated-storage enum. New rows have `session_key:null`, `run_id:''`, `source_publication_id:null`. Dated Course rows use this enum to permit multiple recordings while preserving the separate legacy Course PDF collection.

Recorded Teachers are display/grouping attribution only. `teacher_id` stays NULL and `teacher_ids_json` stays `[]`. Selection requires an active native account with the current scoped TEACHER role or active native Teacher designation. A correction may preserve saved historical attribution; it grants no current access. Correction changes only recorded context/title/draft state. Class/date, permission columns, media links and upload anchors remain unchanged. No legacy row is backfilled or rewritten.

V2 Programme readers require the native class/date audience or current enabled monthly class/month entitlement. The legacy single-class fallback is excluded for V2. Programme Teacher access/contribution requires a current native Teacher role and current active class assignment. Course Teachers use the current Course Teacher role. Recorded labels grant no role, assignment, membership, subscription or management right. Existing legacy audiences stay compatible.

Source denies STUDIO/FROZEN ownership for options and all V2 writes. Native reference guards run through the existing owner transaction: private definitions are captured under the Core fence; current Core Teacher/account facts and ownership are checked in the final transaction. The generic planner is unchanged; there is no direct-binding bypass.

## PDFs, notes and processed content

A V2 note key is `["MEDIA",<exact lesson ID>]` and its immutable `container_id` is that lesson ID. Official PDFs and active dated Teacher notes share the ten-PDF allowance for the exact record. Different null-session records never pool. Replacement preserves note history and its slot. V2 notes have no recurring attachment option. Accepted publication rechecks the combined allowance, including Teacher notes posted after a private Admin draft. Feed/get/download/enrichment use the same exact identity and deduplicate notes. Content feeds retain saved legacy media and omit blank timetable slots.

**Review summary and topics** opens the existing original temporary MP4 attachment’s full canonical companion. It can import a bounded processed JSON file, edit full summary/timestamped topics, save a private processed draft, then separately publish reviewed content. `companion-editor` is current Admin-only and validates the exact attached MP4, original upload and companion expiry. Publication checks current source/draft revisions and duration. The learner allowlist still excludes private processing fields. Original successful upload, fourteen-day recording expiry and independent calendar-month companion expiry remain unchanged. Retained recordings and Studio’s reviewed YouTube/provider workflows keep their existing policies; this feature invents no YouTube upload clock and duplicates no video source.

## Signed Studio contract

`POST /internal/website/media-teachers` uses the existing HMAC envelope, native `sourceRef`, issuedAt window and `purpose:'ADMIN_MEDIA'`. Input includes exact mapped `offeringId` and optional `teacherIds`. Source checks native current session/epoch/account/admission and Global or matching Programme/Course Admin authority before and after selection. Mapping must be enabled and not FROZEN. Studio additionally checks its own current Admin workspace and committed WEBSITE owner around the call and every attach/save/publish.

Response: `{schema:'NATIVE_MEDIA_TEACHERS_V1',offeringId,activityKey,teachers:[{id,name}],classes:[{id,name}],selectedTeacherIds,teacherRequired:true,optionsRevision,checkedAt}`. Course classes are empty. IDs are checked/canonicalized; no identity is provisioned. New exact class/Surah/Teacher read recipes reject SQL, parameter, scope and owner tampering while retaining before/after proof checks.

Existing Core website-platform migrations 0011/0012/0013/0015/0019 and companion migration 0020 are current release-line prerequisites, not new migrations. The local bridge fixture applies them. Existing 0019 already supplies the ownership NOCASE index.
