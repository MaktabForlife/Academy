# Academy PDF bookmarks and volumes V106.66

Public Library PDFs have Save book and Bookmark page actions. My bookmarks is available in the reader and the Browse / For you navigation. Each bookmark belongs to the signed-in Academy account and follows that account across devices. Entries show the selected book/volume and, for page bookmarks, the page label. Opening one restores the exact PDF and its physical page. Removing it changes only that account's bookmark. Visitors can read public PDFs and are prompted to sign in when saving bookmarks. Device PDFs retain annotation/download support but are not saved as account bookmarks.

Every multi-volume PDF card in Browse and For you opens a Choose a volume dialog before loading a collection PDF. The reader Library groups volumes by book and uses the same chooser. Each pane has its own quick volume selector, separate from PDF.js's page-number box. Switching volumes preserves the existing confirmation for unsaved annotations. Direct links and saved bookmarks to an explicitly selected volume reopen that volume without asking again.

The account-scoped `bookmarks/list`, `bookmarks/save` and `bookmarks/delete` APIs accept no caller-supplied owner authority. Even Global Admin can access only their own personal list. The transaction rechecks active account, current credential epoch, session expiry and revocation. Deterministic keys make repeated saves and removals idempotent. Only public Archive download paths are accepted; private URLs and local file references are rejected. UI text is rendered as text, and account changes clear in-memory bookmark lists and reject late responses.

The additive `0025_pdf_bookmarks.sql` migration creates only `academy_pdf_bookmarks`. Its primary key starts with account ID, and each account is limited to 200 entries. Loading the list reads only that account's rows; save and delete affect one entry. There is no bookmark polling, automatic reading-progress sync or database request on page turns. The feature uses the existing Development Worker, database and website, with no new Worker, bucket, credentials or copied Academy data. Existing versions can ignore the extra table when switching branches.

Local validation covers account privacy, new-session reopening, duplicate saves, deletion, invalid sources/pages, the per-account limit, indexed list reads, transaction failures and revocation during writes. Twenty-seven focused release checks pass, alongside the preview packaging and schema round-trip checks. Eight Chrome integration checks pass for the four-volume chooser, quick switching, exact-page reopening, two-pane independence, account changes, phone layout, For you links and visitor sign-in prompts. The existing PDF browser suite also passes annotation defaults, sticky colours, cancellation of an unsaved replacement, annotated downloads, device files and mobile split view. All browser fixtures are synthetic and block external network access. Website packaging and the Development Worker dry run pass.

Deployment applies only the new table migration, then publishes V106.66 from `feature/academy-review-fixes-10660`. Hosted verification reads health routes, public assets and the new table's schema; it does not run bookmark write tests or a regression/load suite against the hosted database.
